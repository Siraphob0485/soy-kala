# Soy Kala — เว็บแกลลอรี่งานกะลามะพร้าว

เว็บร้านซอยกะลา จังหวัดนครนายก สำหรับแสดงสินค้าและรวบรวมรายการสอบถามราคางานผลิตตามออเดอร์ ใช้ Next.js App Router, TypeScript และ CSS ธรรมดา

## เริ่มใช้งาน

ใช้ Node.js 20.9 ขึ้นไป (ตอนสร้างใช้ Node.js 22)

```powershell
cd O:\NEXT\soy-kala
npm install
npm run dev
```

เปิด http://localhost:3000 หากติดตั้ง dependencies แล้ว ข้าม `npm install` ได้
หาก PowerShell ไม่ยอมเรียก `npm.ps1` ลองใช้ `npm.cmd run dev` แทน

## โครงสร้าง

```text
src/
├── app/
│   ├── layout.tsx                 โครงร่วม: เมนู ส่วนท้าย metadata
│   ├── globals.css                สีและรูปแบบ รองรับมือถือ
│   ├── page.tsx                   หน้าแรก /
│   ├── not-found.tsx              หน้า 404
│   ├── products/
│   │   ├── page.tsx               แกลลอรี่ /products
│   │   └── [slug]/page.tsx        รายละเอียด /products/coconut-turtle
│   ├── quote/page.tsx             รายการขอราคา /quote
│   └── how-to-order/page.tsx      วิธีสั่งซื้อและช่องทางติดต่อ
├── components/
│   ├── ProductCard.tsx
│   ├── ProductImage.tsx
│   ├── ProductPhotos.tsx          ภาพใหญ่ รูปย่อย และเลื่อนดูหลายมุม
│   ├── ProductGallery.tsx         Client Component สำหรับกรองหมวดหมู่
│   ├── QuoteProvider.tsx          รายการร่วมทุกหน้าและบันทึกในเบราว์เซอร์
│   ├── AddToQuote.tsx             เลือกสินค้าและจำนวน
│   ├── QuoteLink.tsx              เมนูพร้อมจำนวนรายการ
│   └── QuoteBuilder.tsx           แก้รายการและคัดลอกข้อความไป LINE
├── lib/quote.ts                  ตรวจข้อมูลและสร้างข้อความขอราคา
├── config/site.ts                ชื่อร้าน คำอธิบาย และ URL ติดต่อ
├── data/products.ts              ข้อมูลตัวอย่างและฟังก์ชันอ่านสินค้า
└── types/product.ts              รูปแบบข้อมูลสินค้าและหมวดหมู่
public/images/products/           เก็บรูปสินค้าจริง
```

## ลองแก้ทีละส่วน

1. เปลี่ยนชื่อร้านและคำอธิบายใน `src/config/site.ts`
2. แก้ข้อมูลสินค้าใน `src/data/products.ts` โดยให้ `id` และ `slug` ไม่ซ้ำกัน
3. วางรูป เช่น `turtle.jpg` ใน `public/images/products/` แล้วแก้ `images` ของสินค้าเป็น `["/images/products/turtle.jpg"]` ใส่หลายรูปได้
4. แก้สี `--accent` และ `--background` ใน `src/app/globals.css`
5. ใส่ URL LINE หรือ Facebook จริงใน `contactUrl` ปุ่มติดต่อจึงจะแสดง

สินค้าที่ยังไม่มีรูปจะแสดงพื้นที่ว่างพร้อมชื่อสินค้า ขนาด ราคา และระยะเวลาผลิตต้องสอบถามกับร้านตามรูปแบบและจำนวนที่ต้องการ

หน้ารายละเอียดสินค้ารองรับการแตะเปิดภาพใหญ่ เลือกรูปย่อย ปัดซ้าย–ขวาบนมือถือ หรือใช้ปุ่มก่อนหน้า/ถัดไปและปุ่มลูกศรบนคีย์บอร์ด กดปิดหรือ Esc เพื่อกลับหน้าสินค้า เพิ่มรูปที่ต้องการเผยแพร่ใน `images` ของสินค้านั้นได้ตามลำดับ โดยรูปแรกใช้เป็นภาพหลักในแกลลอรี่ สินค้าที่มีรูปเดียวจะไม่แสดงปุ่มเปลี่ยนภาพ

## แนวคิดที่ใช้

- `page.tsx` กำหนดแต่ละหน้า ส่วน `layout.tsx` ครอบทุกหน้า
- หน้าเว็บเป็น Server Components โดยค่าเริ่มต้น
- `ProductGallery` ใช้ `"use client"` เพราะมี `useState` และการกดกรองหมวดหมู่
- หน้า `[slug]` ใช้ URL เพื่อหาสินค้า และเรียก `notFound()` หากไม่มีสินค้า
- `getProducts()` และ `getProductBySlug()` แยกจุดอ่านข้อมูลไว้ให้เปลี่ยนเป็นฐานข้อมูลภายหลัง

## ตรวจสอบและรันแบบ production

```powershell
npm run build
```

โปรเจกต์ใช้ static export: ผลลัพธ์อยู่ใน `out/` สำหรับ Cloudflare Workers Static Assets ดูขั้นตอนใน `DEPLOYMENT.md` ส่วนทดสอบระหว่างพัฒนาใช้ `npm run dev`

## รายการขอราคา

1. เลือกสินค้าในแกลลอรี่ หรือใส่จำนวนจากหน้ารายละเอียดสินค้า
2. เปิดเมนู “รายการขอราคา” เพื่อแก้จำนวน ลบสินค้า ใส่วันที่ต้องการใช้ และหมายเหตุ
3. กด “คัดลอกรายการ” แล้ว “เปิด LINE ร้าน” จากนั้นวางข้อความและส่งในแชทเอง

เลือกสินค้าซ้ำจะอัปเดตจำนวนล่าสุด ไม่สร้างรายการซ้ำ รับจำนวนเต็ม 1–99,999 ชิ้น หากคัดลอกอัตโนมัติไม่ได้ สามารถเลือกข้อความจากช่องสรุปเพื่อคัดลอกเองได้

รายการเก็บใน localStorage ของเบราว์เซอร์เครื่องนั้นด้วย key `soy-kala:quote:v1` จึงคงอยู่หลังรีเฟรช แต่ไม่ซิงก์ข้ามอุปกรณ์ และยังไม่ถูกส่งถึงร้าน หากเบราว์เซอร์ปิดกั้นการบันทึกจะแสดงข้อความแจ้ง หน้า `/quote/` ตั้งค่า noindex เพราะเป็นรายการส่วนตัวของผู้เข้าชม

## ต่อยอดระบบรับออเดอร์

ตอนนี้มีแกลลอรี่และรายการขอราคาสำหรับคัดลอกไป LINE ยังไม่มีการบันทึกออเดอร์เข้าร้าน ฐานข้อมูล ระบบสมาชิก หรือการชำระเงิน

หากต้องการรับคำขอผ่านเว็บโดยตรง ขั้นถัดไปคือเพิ่ม API ที่ตรวจข้อมูลบน server และฐานข้อมูล จากนั้นเพิ่มหลังบ้านที่มีการยืนยันตัวตนและตรวจสิทธิ์เพื่อจัดการสินค้าและคำขอ ก่อนพิจารณาระบบมัดจำ
